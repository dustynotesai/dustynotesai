# 在 Codex 使用

這是同一份旅行 skill 的執行補充；旅行流程與資料格式仍以 `../SKILL.md` 和 `trip-schema.md` 為準。

## 檔案位置

- 從本次載入的 `SKILL.md` 所在目錄解析 `references/` 和 `scripts/`，不要假設 skill 裝在 `.claude/skills`。
- 在使用者選定的工作資料夾建立 `trips/<城市>-<YYYY-MM>/`。skill 的安裝資料夾只放工具與參考資料。
- 檢查舊行程只查目前工作資料夾及使用者指定的位置，不掃描其他私人目錄。
- 從工作資料夾執行 `node "<skill 絕對路徑>/scripts/build.mjs" "trips/<城市>-<YYYY-MM>/trip.json" --pdf`。
  路徑含空格或中文時仍要加引號；JSON 用 UTF-8 儲存。builder 不需要 npm 套件或 OpenAI API key。

## 提問與查詢

- 以當前環境可用的提問方式收集缺少資料。不依賴只在 Plan mode 才能使用的工具；沒有提問工具就直接在對話列出問題。
- 用可用的網路搜尋和網頁讀取工具查旅行資料，來源附在對應項目。需要互動才能看到的場次，只有實際具備瀏覽器工具時才操作。
- 工具、網路或網站不可用時，交可完成的部分並標未驗證；不要宣稱 Codex 登入後就一定能查看所有網站或即時票價。
- 使用者明確授權的修改、預設與確認略過方式，沿用主 skill「流程」的規則，不因工具差異重新要求批准。

## 建頁與交件

- 先嘗試 builder。驗證失敗時修正這趟 `trip.json`，不要為了通過而刪掉驗證或編造資料。
- Node 不可用時可用主 skill 的瀏覽器模板方式；沒有命令／檔案工具時，按 `output-template.md` 交 Markdown 並說明尚未建立 HTML／PDF。
- 以這次執行結果確認實際交付的檔案。舊 PDF 存在不代表本次更新成功；PDF 失敗或未重建時，說清楚應從最新 HTML 列印。
- 有瀏覽器工具才做手機／桌面及互動檢查，沒有就說明未做畫面驗證。不要把未執行的檢查算作通過。
- 使用環境支援的可點擊本機檔案連結交件；不要把電腦上的路徑改寫成不存在的 `sandbox:` 下載連結。
- **交件那則訊息一定要貼「出發前自己對的清單」表格**（每行開頭 ☐，見主 skill 第 6 步第 3 點）。只放行程頁連結不算交完——他最後讀的是你的回覆，不一定會打開頁面。
