# 輸出模板（Markdown）

他只要表格、不要行程頁的時候用這一份；要行程頁就寫 `trip.json`（見 [trip-schema.md](trip-schema.md)），結構一樣。
順序：骨架建議（沒訂才有）→ 表頭 → 每一天 → 最後的連結。規則在 ../SKILL.md，這裡只有格式。

## 欄位規則

- **時間** 當地時間、24 小時制。航班跨日寫明抵達日期。移動格寫發車時間，抵達另開一格。
- **活動** 地點加動作，一行。景點寫定案，不寫「A 或 B」。餐廳寫「午餐（附近選一家）」，
  2–3 家同區選項（查過那天有開）放原始備註。
- **排序** 同一天照地理順序，不走回頭路。主線只放值得專程去的，其他行程狀態標備選。
  退房日、移動日第一格先寫寄行李（飯店或車站寄物櫃），再排景點。
- **類型** 交通／景點／美食／拍照／住宿／購物，六選一。
- **城市** 分段和地圖用。
- **行程狀態** 規劃中／備選／已取消／沒去／已到訪。**只有真的走過才標已到訪。**
  已取消和沒去優先，那一格不再提醒訂位。
- **定時票** 必要指示寫場次和名額：「查詢時有位（YYYY-MM-DD）」或「查詢時已滿，改 15:30 場」。
  查不到名額寫「名額未驗證」。換了場次，整天的時間一起改。
- **訂位狀態** 未訂／需預約／已訂／待確認。**已訂要有確認信。** 只有付款授權、
  只有預先入住登記、票券還沒收到 → 待確認。已訂不代表已到訪。
- **每人費用／當地幣** `€18／人`。免費寫「免費」。估的寫「約」。含在聯票寫「已含 <聯票名>」。
  換算成本幣：`€18／人（約 US$20，匯率 YYYY-MM-DD）`。算不清楚寫「待確認」。
- **全部人數總額／付款狀態** `€36／2 人已付`、`€80／2 人付款授權`。沒有付款就留空。
- **必要指示** 看手機就能照做的一兩句：幾點到、哪個入口、帶什麼、下一段怎麼接、行李。
  **理由不放這裡。** 每一個具體數字若不是這次查的，加「（未驗證）」。
- **地圖** 一個連結。
- **官方售票** 官方售票網址。查不到就寫「未驗證」，不要放搜尋結果。
