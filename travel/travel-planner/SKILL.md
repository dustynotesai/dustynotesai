# Travel planner — 先問、再查、給他看過，才交

一句話：**chatbot 給答案，agent 去查。** 這份 skill 從一趟真的走完的十五天歐洲行逆推出來——
兩個晚上、約 6.8 小時的來回排完，每天的主要景點大致上都照著走了。

**違反字面就是違反精神。**

## ⭐ 用他的語言，從頭到尾

他用什麼語言寫給你，**每一組問題、讀回去的那一句、每天的大綱、行程頁上的字，全部都用那個語言**。
第一組中文、第二組跳回英文是最常見的破綻——他中途不會換語言，你也不准換。
⚠️ 這條跟幣別那條不衝突：語言跟著他，**幣別要單獨問**，不准從語言猜。

## 流程（✋ 是一定要停下來等他的地方）

| 步 | 做什麼 | 停在哪 |
|---|---|---|
| 0 | 看他的舊行程：改哪一趟，還是排新的一趟；上次去過哪裡 | ✋ 有舊行程就先問 |
| 1 | 問六題 | ✋ 讀回去，他說對 |
| 2 | 骨架還沒訂：排城市和晚數、比機票和城市之間的交通、推薦住宿 | ✋ 他選好或訂好，讀回去 |
| 3 | 查：班次、場次名額、營業日、那一天城裡的活動、價格 | |
| 3b | 排大綱之前再問一組：最想要的三樣、走路量和幾點出門、一定要去和一定不去 | ✋ 他答完 |
| 4 | 每天一段大綱 | ✋ 他說好 |
| 5 | 寫完整版 `trip.json` | |
| 6 | 建行程頁，交件：**這是第一版，不是定案** | |
| 7 | 他看完要改：只改受影響的部分，重建，說清楚改了什麼 | ✋ 改之前讀回去要改什麼 |

他只要表格、不要頁面：第 5 步照 [references/output-template.md](references/output-template.md) 寫 Markdown，跳過第 6 步。

## 0. 先看他的舊行程

**一趟一個資料夾：`trips/<城市>-<YYYY-MM>/`**（例如 `trips/東京-2026-12/`），裡面放 `trip.json`、`trip.html`、`trip.pdf`、`photos/`。
同一個城市同一個月已經有了、又是另一趟，就加 `-2`。

開始之前，在他的工作資料夾找 `trips/*/trip.json`（最上層有一份 `trip.json` 也算，問他要不要搬進 `trips/`）：

- **沒有舊行程**：直接到第 1 步。
- **他說的跟某一趟對得上**（同城市、日期重疊）：**先問「改這一趟，還是排新的一趟？」** 沒問不准覆蓋任何 `trip.json`。
  改舊的就只動那個資料夾，其他趟不碰。
- **要排新的一趟，而且去過同一個城市或國家**：讀舊的 `trip.json`，
  - 行程狀態是「已到訪」的：**這次預設不排**，讀回去時列給他看——「上次去過：＿、＿，這次不排，想再去就說」。
  - 舊行程日期已經過了、格子卻還是「規劃中」：不知道他去了沒，**列出主線的點問他哪些去過**，一次問完。
  - 「沒去」的：可以當這次的候選。
  - 上次的幣別、護照、預算、步調、行李，**當這次的預設讀回去確認**，不用每題重問。

## 1. 問，問完讀回去

沒問就排，等於 ChatGPT。**他說「趕時間、直接給我」也一樣要問**，只是只問這六題。
**分兩組問：先 1–3，他答完再 4–6。每組就是三題，不准塞第四題。** 給選項。
完整題目和每一題的理由在 [references/interview.md](references/interview.md)。

1. 幾號到幾號、從哪裡出發
2. 幾個人、跟誰
3. **價格用哪個幣別看**——單獨問，**不准從他用的語言猜**
4. 預算：每人每天大概多少（用第 3 題的幣別，不含機票住宿）
5. 步調：滿檔／平均／放空
6. 機票、住宿、城市之間的交通：都訂了／訂了一部分／都還沒訂

**第一輪就是這六題，不多不少。** 出國要問的護照和租車放到第 2 步那一組（骨架還沒訂的話），
骨架都訂好了就跟 3b 那一組一起問——兩個都在查資料之前，入境規定和國際駕照照樣查得到。
⚠️ 以前這兩題掛在第 1 步，第一輪就變成八題；表頭寫六題、實際問八題，使用者會當場愣住。

**✋ 讀回去：「我聽到的是……，對嗎？」他說對，才開始查。**

## 2. 骨架還沒訂：先排機票、住宿、城市之間的交通

第 6 題沒全訂才做。**只查、只比、只推薦、給連結——不替他訂。**

1. **城市和晚數**：照地理順序，不走回頭路；一個城市至少兩晚。「甲地進、乙地出」的機票要拿來比。
2. **機票**：每一段 2–3 個選項——直飛或轉機、總時間、行李額、每人價格、**查詢時間**。
3. **城市之間：火車、飛機、巴士並排比，不准只給一種。推薦要同時看時間和價格。**
   - **門到門時間一段一段加**：飯店到車站或機場＋提早抵達（飛機通常 2 小時）＋安檢和託運＋坐車或飛行
     ＋落地到市區。**只比「坐在車上」或「在天上」的時間是錯的。**
   - **總花費一起算**：票價＋託運行李＋到機場和進城的交通。
   - **推薦一句話講出取捨**：「兩種門到門差不多，火車每人便宜約 ＿」或「飛機快 ＿ 小時，每人多 ＿」。推薦的標 ⭐。
   - 其他照比：行李限制、轉乘次數、要不要訂位、什麼時候開賣（越早買越便宜的要寫）。
4. **住宿：直接推薦。** 先定區域（離車站或主線近、拖行李好走、晚上安全），每個城市 2–3 家：
   ⭐ 推薦一家，一句理由對上他的預算、步調和隔天第一站；另外一家便宜一點、一家位置或景觀好一點。
   每家寫每晚價格（查詢日期）、到車站幾分鐘、免費取消到哪天、連結。

**✋ 他訂好、告訴你訂了什麼，讀回去確認，才排每一天。**

**選好了還沒訂、想先看行程——照他選的排：**
讀回去他選的；表頭寫「**骨架已選、未訂：<哪幾項>**」（沒選的另寫「骨架未定」）；那幾格訂位狀態寫「未訂」；
表頭下放「**先訂這幾樣**」，最容易賣完或漲價的在最前面。他訂的跟選的不一樣，**受影響的那幾天整天重排**。

## 3. 查：查得到就查，查不到就標「未驗證」

逐項要查什麼、例子、常見的藉口在 [references/research.md](references/research.md)。五條不能退：

1. **不編。** 網址、班次號、價格、營業時間、匯率——**這次用工具查過**，或**標「未驗證」**。記憶裡的算後者。
2. **價格寫查詢時間。** 先寫當地幣、每人；換算成他的幣別標「約」和匯率日期。每人價和總額分開寫。
3. **定時票先查場次名額，再排那一天。** 有位的場次先卡進去，其他點圍著它排；想要的滿了，換場次、**整天重排**。
4. **查那一天城裡發生什麼事**：國定假日、罷工、比賽、遊行、封路；公車地鐵停了，寫替代方案。
5. **沒有上網工具**：輸出第一行寫「這一版沒有查證，所有班次、連結、價格都是未驗證。」

**查的份量——他在旁邊等，不能查到天荒地老：**

- **開始查之前說一句要查哪幾樣**（例如「機場到市區兩段、三家飯店」），**查完整理好一次交**。
- **查超過十幾次就在中間再說一句現在查到哪**（「機票比完了，開始查住宿」）。
  他看著一排工具在跑、沒有人講話，**會以為當掉了**——第一次用的人尤其會。
  這不是「又查到了」的事後補充，是讓他知道還在動。
- **不開子 agent、不在背景查。** 自己查，查完整理好才回他；交完就停，不要事後再補一則「又查到了」。
- **每一步只查會改變排法的東西：**

  | 步驟 | 查 | 不查（留到下一步或出發前） |
  |---|---|---|
  | 骨架 | 機場／城市之間的交通、2–3 家住宿 | 每一種房型、每一個方案 |
  | 大綱 | 定時票和開賣日、主線景點的休息日和最後入場、區域之間怎麼移動、那幾天城裡的活動 | 店家營業時間、餐廳名字、票價細節 |
  | 完整版 | 每一格的價格、營業時間、餐廳 2–3 家、官方連結 | 同一個數字換第三個網站再查 |

  **大綱每一天查 5 次左右、完整版每一天 10 次左右就要收。** 超過了，剩下的標「未驗證」往下走。
- **每一個數字最多試兩次**：官方站一次、一個訂房或比價網站一次。查不到就標「未驗證」附搜尋連結，**往下走**。
- **住宿每個城市查到 2–3 家就停。** 價格用列表頁或搜尋結果看得到的「查詢時最低價」加查詢時間，
  **不要一家一家翻所有房型和方案**。
- 網頁要點選才出得來、又沒有瀏覽器工具：直接標「未驗證」附連結，請他訂的時候自己看。
- **讀網頁用網頁讀取工具，不要自己下 `curl`、`wget`**——會跳權限問他，網站也常擋。
- **查到跟之前寫的不一樣**（路線、轉乘、票價、營業時間）：**同一件事出現在別的格子、別天、回程，全部一起改**，
  不要只改查到的那一格。

另外三件一定要查，不要等他問：

- **出發前要準備**：依他的**護照國籍**查簽證或入境許可、護照效期；有租車就查國際駕照；保險。
  寫進表頭下的「出發前要準備」（`trip.json` 的 `meta.prep`），附官方連結。
- **聯票、交通卡算過才推薦**：照他的行程逐項加總，比單買划不划算；寫清楚**能用幾天、含哪些、
  能不能隔天再進、要不要先開通**。買票那天放一格，之後的格子費用寫「已含 <票名>」。
- **看天氣的日子排雨天備案**：戶外為主（山、海、花園、拍照）的那天，先留意寫「下雨改 ＿＿」，
  再加一格「備選」的雨天行程。

## 3b. 排大綱之前，再問一組（三題）

第 1 步的六題決定查什麼，**這三題決定每天排什麼**。沒問就排，主線是你挑的，不是他要的。

1. **最想要的三樣**：美食／歷史／海／山／拍照／購物／夜生活，選三個**排順序**
2. **一天走多少沒問題**（5 km／10 km／不設限）、爬樓梯 OK 嗎、**幾點出門**（07:00／09:00／10:00 以後）
3. **一定要去、一定不去**：各列三個

他趕時間就用預設——平均走路量、09:00 出門、沒有硬指定——**但表頭要寫出來**，
他才知道這幾件事是你替他決定的。

其餘（飲食、拍照到什麼程度、行李、交通偏好、租車）第 5 步真的用到那一格再問，
一次問完，不要一題一題來。完整題目和每一題的理由都在
[references/interview.md](references/interview.md)。

## 4. 每天一段大綱

```
Day 02 · M/D（週X）· <區域甲> → <區域乙>
主線：09:00 <景點甲> → 12:00 午餐（附近選一家）→ 14:30 <景點乙>
今晚：<住宿>
時間節點：14:30 <景點乙>定時票（查詢時有位，<查詢日>）
先留意：<那一天最需要知道的一件事>
這天：未驗證 2 項 · 需預約 1 項
```

**✋ 他改，你修，再給他看，直到他說好。** 說好之前不寫完整版。

## 5. 排的原則

- **骨架固定，只填中間。** 機票、住宿、城市之間的交通是骨架。
- **路線要順**：同一天照地理順序，不走回頭路。**主線只放值得專程去的**，其他標備選。
  走完的那趟，使用者最滿意的就是這兩件。
- **行李**：退房日、移動日，先把行李放進飯店或車站寄物櫃，**不拖行李逛景點**。
  寄物寫在哪、多少錢、人工還是自助、貴重物隨身。這是那一趟使用者一天一天改過來的。
- **第一天排鬆**，落地調時差。**移動日只留一件硬行程**，其他算備選。
- **餐廳給選項**：每一餐同區 2–3 家（查過那天有開），活動寫「午餐（附近選一家）」。他會現場自己選。
- **每個國家的火車只推薦一個官方 app**，寫它能做什麼（瑞士：SBB Mobile 買票、查班次、看月台）。
- **狀態分兩欄**：行程狀態（規劃中／備選／已取消／沒去／已到訪——真的走過才標已到訪）；
  訂位狀態（未訂／需預約／已訂——有確認信才算／待確認）。
- **必要指示一兩句**，看手機就能照做：幾點到、哪個入口、帶什麼、下一段怎麼接。理由放備註。
- **表頭第一行、交件時都要說**：這是一份大綱，給他全貌——用什麼 app、哪些地方值得去；
  不是每個點都要去，去不去照當下的感覺。

## 6. 建行程頁、交件

1. 照 [references/trip-schema.md](references/trip-schema.md) 寫 `trip.json`，存在這一趟的資料夾 `trips/<城市>-<YYYY-MM>/`。
2. 跑 `node <這個 skill 資料夾>/scripts/build.mjs trips/<城市>-<YYYY-MM>/trip.json --pdf`，
   得到同名的 **`trip.html`（完整版）和 `trip.pdf`（A4 精簡版：每天的簡報、必要指示、連結）**。
   - **直接跑，不用先檢查 Node 或 Chrome 在不在**（去翻系統資料夾會跳權限問他）。
     沒有 Node，指令會說找不到；沒有 Chrome，build 會自己說 PDF 沒印。
   - **build 停下來列了清單**：照清單改 `trip.json` 再跑，**不要繞過檢查**。
   - **地圖**：景點／美食／拍照／住宿／購物的格子**每一格都要有 `map`**。交通不用；
     在車上、機上那種沒有地點的格子 `city` 寫 `Transit`，也不用。缺了 build 會停下來。
     - 查到座標就用座標：`?api=1&query=<緯度>,<經度>`——他一點就開在那個點上。
     - 沒有座標就寫**地點名加城市**：`?api=1&query=淺草寺 東京`。
       只寫店名會開出一列搜尋結果，**他還是要自己找一次，那這個連結就沒有用**。
     - **不要組 `/maps/place/` 那種帶 CID 的網址，也不要短網址**——沒查過就是編的，
       而且短網址看不出指去哪裡。build 只收 `google.com/maps/search/`。
   - **訂得到的連結**（`ticket`）：**住宿還沒訂的格子一定要有訂房連結**（飯店官網或訂房網），
     沒有連結他訂不了；已經訂了的補一個也好，他到現場要找地址和電話。
     **定時票、名額制的景點和拍照行程（訂位狀態「需預約」）也一定要有官方訂票連結。**
     餐廳還沒選定（「附近選一家」那種）可以沒有連結，但**必要指示要寫清楚怎麼訂**——
     電話、現場候位、旺季要多久前訂。缺了 build 會停下來或警告。
   - **照片**：城市和景點用 Wikimedia Commons 的檔名，**確定是那個地方才放**；他自己的照片用 `file`。
     **每一段城市都要有一張圖**（`sections[].photo`），缺了或抓不到 build 會停下來——
     檔名編的跟真的長得一樣，只有抓下來才知道。格子裡的小圖抓不到只會警告，頁面照樣出來。
   - **PDF 沒出來**（找不到 Chrome）：跟他說，用瀏覽器打開 `trip.html` → 列印 → 另存成 PDF，
     頁面自己有列印版面，印出來一樣是精簡版。
   - **沒有 Node**：把 `scripts/template.html` 和 `scripts/render.js` 複製到一起，把 `trip.json` 貼進去，
     用瀏覽器打開；要 PDF 一樣用瀏覽器列印。
   - **交件前看一次成品**：有瀏覽器工具時，用手機（約 390px）和桌面寬度打開產生的 HTML，
     確認沒有橫向溢出，試一次日期跳轉和備註展開；「出發前待處理」要包含需預約、未驗證與待確認的項目，
     已取消或沒去的項目不列入。有 PDF 下載連結就確認檔案能開。修正發現的問題後確認一次即可；
     沒有瀏覽器工具就檢查產出檔案，交件時說明尚未做畫面與互動檢查。
3. 交件時給他：兩個檔案的位置、「出發前要準備」、「未驗證／待確認」清單、「先訂這幾樣」（如果有）、
   上面那句「這是一份大綱」，**還有這一句：「這是第一版，不是定案。讀一遍，想改什麼直接跟我說——
   換飯店、刪一個點、兩天對調都可以，我改好重建。」** 頁面的 `meta.notice` 也要寫這句。
4. 之後要改：改那一趟的 `trip.json`，重跑 build。
5. **回來之後**：跟他說「旅行回來告訴我哪些去了、哪些沒去」，把那幾格改成「已到訪」或「沒去」重跑 build——
   下次排同一個地方，就不會再推一樣的。
6. **要分享出去**：訂單號、姓名、票券條碼、私人郵件連結本來就不寫進 `trip.json`；
   其他不想公開的字（家在哪、同行的人）寫一份遮蔽規則，用 `--redact 規則.json` 建。

## 7. 他看完要改

例如「我自己找到飯店了，改住 ＿＿」「第三天太趕，刪掉一個點」「鎌倉跟池袋兩天對調」。

1. **✋ 讀回去要改什麼**：「改住 ＿＿，已經訂好了（還是還沒訂？），對嗎？」
2. **找出會跟著變的地方，只重查這些**：
   - 換住宿 → 每天的「今晚」、入住和退房那兩格、退房日寄行李、機場／車站到飯店的交通、每天第一格從哪裡出發
   - 刪一個點或兩天對調 → 那幾天的主線順序、區域之間的移動、定時票的日期、雨天備案
   - 他自己找的飯店也要查：地址、最近的車站、入住退房時間；價格和取消規定他訂了就以他說的為準
3. **改 `trip.json`，重跑 build**。其他沒受影響的格子不要動，也不要順便「優化」。
4. **交件時列清楚**：「改了：＿、＿；因為換飯店跟著改了：＿；沒動：其他天」，附新的 `trip.html`、`trip.pdf`。
5. 改完一樣是第一版——他還可以再改。

## 紅旗，看到就停，回到出錯的那一步

- 還沒讀回去確認，就開始查；沒給他看大綱，就交完整版
- 幣別是猜的
- 替他訂了任何東西
- 城市之間只給一種交通方式
- 價格沒寫查詢時間；每人價和總額寫在同一格
- 一個數字、網址或匯率，說不出「這次用什麼工具查的」
- 「應該是」「通常是」「一般來說」出現在表格裡
- 場次滿了或他訂的跟選的不一樣，只改一格、沒整天重排
- 去程查到路線寫錯改好了，回程或別天同一段還是舊的
- 骨架沒訂就交每天的行程，表頭沒寫「骨架已選、未訂」或「骨架未定」
- 退房日或移動日，行程裡拖著行李逛景點
- 出國的行程沒有「出發前要準備」，或簽證寫的是記憶不是查的
- 推薦了聯票或交通卡，卻沒照他的行程算過、沒寫能用幾天
- 整天在戶外、要看天氣的那天，沒有雨天備案
- 「已訂」寫成「已到訪」；必要指示超過兩句或在講理由
- 沒問就覆蓋了一份已經存在的 `trip.json`，或把新的一趟寫進舊的資料夾
- 他要改一件事，你只改了那一格，跟著會變的（今晚住宿、交通、出發點）沒改；或者順便改了他沒要求的地方
- 交件時沒說「這是第一版，想改直接說」
- 舊行程裡「已到訪」的點又排進主線，卻沒跟他說
- build 報錯，你去改 build 或跳過檢查，而不是改 `trip.json`
- 有地點的格子沒有地圖連結，或哪一段城市沒有圖——交出去的第一版就該是齊的
- 住宿還沒訂卻沒有訂房連結，或需預約的景點沒有官方訂票連結——他還是得自己去搜一次
- 為了讓 build 過，編一個 Commons 檔名或組一個 Google Maps 地點網址
- 開了子 agent、在背景查，或交完之後又補一則「又查到了」
- 大綱階段在查店家營業時間、挑餐廳名字——那是完整版的事
- 整份沒有一個「未驗證」——不是你全查到了，是你沒標
